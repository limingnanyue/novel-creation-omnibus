# 修改工作流 · Revision Workflow

## 适用场景
- 初稿完成后的修改
- 结构性重写（大改）
- 逐句精修（小改）
- 读者反馈整合

---

## 1. 修改的四个层次

| 层次 | 改什么 | 什么时候做 | 耗时比例 |
|:-----|:-------|:----------|:---------|
| 🏗️ 结构修改 | 大纲/情节/节奏/POV/章节顺序 | 第一次修改 | 40% |
| 📐 章节修改 | 每章的起承转合/信息量/密度 | 结构确定后 | 25% |
| ✏️ 逐句精修 | 句子流畅度/用词/节奏 | 章节确定后 | 25% |
| 🔍 最终校对 | 错别字/标点/格式 | 发布前 | 10% |

---

## 2. 结构修改

### 2.1 结构自检清单
- [ ] 故事的起承转合是否完整？
- [ ] 章节顺序是否最佳？（有没有可以调换的？）
- [ ] 节奏是否有长篇平坦区？（连续5章无事发生）
- [ ] 每条线是否都有推进？
- [ ] 角色的动机是否前后一致？
- [ ] 有没有可以合并的章节？
- [ ] 有没有需要拆分的章节？
- [ ] 信息释放的顺序是否合理？
- [ ] flashback的位置是否合适？
- [ ] 高潮是否在最佳位置？

### 2.2 结构修改的"打乱重排"法
1. **提取每章的核心事件**（1句话概括）
2. **打乱所有卡片**
3. **重新排列**（新的可能比原来的好）
4. **去掉没有推动力的章节**（删了也不影响故事的）
5. **标记需要新增的连接章节**

### 2.3 添加删减的判断标准
| 判断标准 | 保留 | 删除 |
|:---------|:-----|:-----|
| 推动情节 | ✓ 保留 | — |
| 塑造人物 | ✓ 保留（但可浓缩） | — |
| 建立氛围 | ✓ 保留（但不过量） | — |
| 提供信息 | ✓ 保留（但换位置） | — |
| 以上都不符合 | — | ✗ 删除或合并 |

---

## 3. 章节修改

### 3.1 每章的三段式检视
```
开头 → 前3段是否抓住读者？
中段 → 信息量是否适中？节奏是否恰当？
结尾 → 是否有章末钩子或情感收束？
```

### 3.2 章节修改的"五问法"
1. **这一章的核心是什么？**（1句话能说清吗？）
2. **读者读完这一章的情绪是什么？**（兴奋/感动/紧张/无聊）
3. **有没有可以删掉的段落？**（对核心无用的=删）
4. **有没有可以浓缩的段落？**（太啰嗦的=剪）
5. **结尾是否让读者想读下一章？**（不是=重写结尾）

### 3.3 对话修改的专项检查
- [ ] 每个角色的语气是否一致？
- [ ] 对话是否有"信息炸弹"（太明显的信息输送）？
- [ ] 对话中是否有可以转化为潜台词的部分？
- [ ] 对话前后的动作/神态是否缺失？
- [ ] 对话是否过长需要穿插？

---

## 4. 逐句精修

### 4.1 句子层面的"七刀"
| 刀数 | 剪什么 | 修改方向 |
|:-----|:-------|:---------|
| 1 | "XX地/XX的" | 替换为具体动作 |
| 2 | 被动语态 | 改主动语态 |
| 3 | "很/非常/特别" | 删除后用具体描述 |
| 4 | "开始/继续/持续" | 直接写动作 |
| 5 | "感到/觉得/意识到" | 直接用感受呈现 |
| 6 | "仿佛/似乎/好像" | 删除2/3 |
| 7 | "是……的"句式 | 简化 |

### 4.2 用词多样化的三个原则
1. **不为换而换** — 同一个词隔两三句再用没问题
2. **语境优先** — 用最准确的词，不是最复杂的词
3. **角色对话用词要匹配人设** — 大学教授和街头混混用词不同

### 4.3 节奏的句子级调整
```
短句（<10字）：加速、制造紧张
中句（10-20字）：标准叙事节奏
长句（20+字）：放缓、制造沉浸感
```
- 连续3个短句 → 读者紧张
- 连续3个长句 → 读者疲劳
- 短长交替 → 最舒适的阅读体验

## 5. 读者反馈整合

### 5.1 反馈分级处理
| 反馈类型 | 优先级 | 处理方式 |
|:---------|:-------|:---------|
| 逻辑bug | 🔴 立即 | 无条件修正 |
| 角色行为矛盾 | 🔴 立即 | 检查人设是否一致 |
| 节奏问题（太慢） | 🟡 高 | 缩短相关章节 |
| 情感不够 | 🟡 高 | 增加情感描写/内心戏 |
| 设定看不懂 | 🟡 中 | 简写设定/加注/信息前置 |
| 个人口味问题 | 🟢 低 | 考虑但不必须 |
| "我觉得应该写成X" | ⚪ 参考 | 感谢但不采用 |

### 5.2 修改的"度"
- **不要被读者牵着走** — 每个读者都是编辑，但不是每个都对
- **多数人反应 = 问题** — 如果5个人说同一问题，必须改
- **少数人的强烈建议 = 有道理但未必适合** — 考虑核心方向是否一致

## 6. AI味检测·修改相关

### 检查清单
- [ ] 是否跳过了结构修改直接进入精修？
- [ ] 每个章节是否能1句话说清核心？
- [ ] 结尾有钩子吗？没有→重写
- [ ] 是否删除了5%以上不必要的字数？
- [ ] 对话是否有"信息炸弹"？
- [ ] 长句短句是否交替使用？
- [ ] 是否有读者指出过的同一问题未改？
- [ ] 不同层次的修改是否按顺序而非跳跃进行？

## 7. 8 类一致性检查（CT1-CT8，v6.0 集成）

> 来源：novel-audit-v6.0.0 · `renovel_consistency.json`（v1.4）
> 6+1 道门禁的具体落地项。修改时必须逐条对照，涉硬矛盾必须立即修正，优先级高于任何剧情/人设建议。

| ID | 检查类型 | 判定要点 | 严重度 |
|:---|:---------|:---------|:-------|
| **CT1** | 时间矛盾 | 时间标记前后矛盾（上午变傍晚、三天变一周） | 🔴 硬伤 |
| **CT2** | 地点矛盾 | 角色位置冲突（A在京城却出现在江南场景） | 🔴 硬伤 |
| **CT3** | 道具消失 | 使用了 `items_held` 中没有的道具 | 🔴 硬伤 |
| **CT4** | 角色信息越界 | 角色知晓不该知道的信息（未被告知却知道秘密） | 🔴 硬伤 |
| **CT5** | 性格不一致 | 对白指纹违背角色 MBTI/声线设定 | 🟡 软伤 |
| **CT6** | 设定矛盾 | 能力/规则前后不一致（金手指强度变化） | 🔴 硬伤 |
| **CT7** | 数量/单位错误 | 数字与上文不符（三人变五人、百两变千两） | 🟡 软伤 |
| **CT8** | 称谓错误 | 角色关系称谓前后不同（表哥变堂哥） | 🟡 软伤 |

**硬约束**：CT1-CT4/CT6 涉事实硬矛盾，在修改中**优先级最高**——任何剧情/人设/节奏建议若破坏事实一致性，必须让路。

## 8. 交叉审计仲裁规则（v6.0 集成）

> 来源：novel-audit-v6.0.0 · `cross_cut_matrix.md`（v4.5）
> 修改时多视角碰撞，避免单视角盲区。

### 8.1 六个交叉区

| 交叉区 | 碰撞视角 | 检查内容 |
|:-------|:---------|:---------|
| **CC1** 对白自然度 × 人设 | 去AI味 vs 角色声线 | 对白去AI味但不能破坏角色辨识度 |
| **CC2** 伏笔铺设 × 回收 | 剧情逻辑 vs 事实一致 | 伏笔回收时是否悄悄改了既定事实 |
| **CC3** 人物驱动 × 剧情推进 | 角色动机 vs 剧情需要 | 情节是角色选择驱动还是机械降神 |
| **CC4** 世界观 × 设定自洽 | 事实一致 vs 爽点平衡 | 金手指代价前后是否一致 |
| **CC5** 开篇钩子 × 平台留存 | 钩子质量 vs 平台适配 | 开篇能否留住对应平台读者 |
| **CC6** 整体节奏呼吸感 | 微观节奏 vs 整体完成度 | 张弛是否得当，全程高能会疲劳 |

### 8.2 四条仲裁规则

1. **去重**：两视角对同一问题都报 → 合并为一条，severity 取较高者
2. **冲突消解优先级**（硬排序）：
   - 硬事实冲突（CT1-CT4/CT6）→ **事实判定优先**，剧情/人设让路
   - 声线 vs 去AI味（CC1）→ 以"不破坏角色辨识度"为底线，最大化去AI味
   - 节奏 vs 剧情（CC6）→ 优先保"读者不弃读"
3. **互补合并**：两视角从不同角度指出同一区块 → 合并为带双视角的复合建议
4. **无法调和**：两视角根本性矛盾 → 保留两条，标注 `conflict_pending`，提示人工裁决

> **总纪律**：宁严勿宽——分歧存疑时一律按"有问题"处理。
